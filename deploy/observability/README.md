# Observability for drbrain

`drbrain` serves Prometheus metrics on its own listener, separate from the game
listener so nginx never proxies `/metrics` to the public vhost. Perses reads
that Prometheus and serves the operator dashboards.

|setting|default|meaning|
|---|---|---|
|`DRBRAIN_METRICS_ADDR`|`127.0.0.1:9095`|Metrics listen address; empty disables the listener|
|`DRBRAIN_PROMETHEUS_PORT`|`9091`|Host port for the Prometheus UI/API in compose|
|`DRBRAIN_PERSES_PORT`|`9092`|Host port for the Perses UI in compose|

## Run it

```bash
just restart                     # drbrain on the host, metrics on 127.0.0.1:9095
curl -s http://127.0.0.1:9095/metrics | grep '^drbrain_'

cd deploy/observability
docker compose up -d
```

- Prometheus: <http://127.0.0.1:9091> — TSDB in the `prometheus-data` volume,
  15-day retention.
- Perses: <http://127.0.0.1:9092> — dashboards live in the `perses-data` volume.

Both UIs are published on `127.0.0.1` only. Perses runs with auth disabled, so
do not expose its port; its datasource proxy is restricted to the compose
`prometheus` service.

## Dashboards

The dashboard is Go code: `perses/dac/main.go`. It is a standalone Go module so
the Perses SDK never enters the drbrain server build. Compose mounts
`perses/provisioning/` read-only and Perses re-injects it every hour.

|file|role|
|---|---|
|`dac/main.go`|**source of truth** for the dashboard|
|`dac/go.mod`, `dac/go.sum`|isolated Perses SDK dependencies|
|`provisioning/project.json`|`drbrain` project|
|`provisioning/datasource.json`|default Prometheus datasource through the Perses proxy|
|`provisioning/dashboard.json`|generated by `perses-build`; do not hand-edit|

The dashboard opens at
<http://127.0.0.1:9092/projects/drbrain/dashboards/drbrain-delivery>.

### Iterate and apply

Edit `dac/main.go`, then:

```bash
just perses-apply
```

`perses-apply` depends on `perses-build`, which runs:

```bash
cd deploy/observability/perses/dac
go run . --output json |
  jq 'del(.metadata.createdAt, .metadata.updatedAt, .metadata.version)' \
  > ../provisioning/dashboard.json
```

then applies the provisioning folder with `percli` inside the Perses container.
`perses-apply` lints first with `percli lint -d /etc/perses/provisioning --online`,
so server-side schema errors stop the apply before anything changes.

Use `just perses-build` alone when you only want to inspect the generated JSON.
`percli dac build -f main.go -ojson` is the official equivalent; `go run` avoids
requiring the CLI on the host.

Validate manually without applying:

```bash
docker compose -f deploy/observability/compose.yaml exec -e HOME=/tmp perses \
  percli login http://localhost:8080
docker compose -f deploy/observability/compose.yaml exec -e HOME=/tmp perses \
  percli lint -d /etc/perses/provisioning --online
```

Perses re-reads the provisioning folder on startup and every hour, and
`enable_watch: true` watches for file events. Docker Desktop did not deliver
host filesystem events into this bind mount during testing, so treat
`just perses-apply` as the reliable loop; a restart
(`docker compose ... restart perses`) also re-applies everything.

The UI is useful for previewing panels, but UI edits are overwritten by the
next apply. Port a prototype back into `dac/main.go`; do not edit
`provisioning/dashboard.json` directly.

## Delivery money

`drbrain_delivery_money{city="…",session="…"}` is the current cash balance of
every delivery session held in memory. A save that is not loaded is not read:
scraping never scans PostgreSQL. Sessions are the raw series on purpose, so
PromQL can aggregate per city:

```promql
# one line per live session
drbrain_delivery_money

# total cash per city across live sessions
sum by (city) (drbrain_delivery_money)
```

## Linux note

Docker Desktop (macOS/Windows) forwards `host.docker.internal` to the host's
loopback, so the defaults work. On Linux the container reaches the host through
the bridge gateway, which cannot connect to a listener bound to `127.0.0.1`:
set `DRBRAIN_METRICS_ADDR=0.0.0.0:9095` and firewall port 9095 to the Docker
bridge.
